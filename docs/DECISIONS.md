# Design tradeoffs

- **Preserve the repository and original baseline.** The explicit user request authorizes improving QueryPilot. Preserve Git history, original tests/data and deterministic evaluator; build a new investigation API around them. Backend/frontend top-level folders follow the existing framework layout.
- **LangGraph for the inner agent loop.** A bounded graph makes tool/correction/publication stages explicit. Durable outer admission/events use PostgreSQL. No multi-agent swarm, Temporal dependency or MCP wrapper is added for appearance; SQL authority must remain application-owned. The graph runs in process; interrupted paid execution requires explicit resubmission.
- **SQLGlot plus database authority.** AST scope handles syntax/CTEs/quoted identifiers better than regex. The dedicated role/read-only transaction enforces an independent database boundary. Neither proves arbitrary business correctness.
- **Official synchronous SDK in a synchronous worker.** FastAPI synchronous handlers run through its thread pool; paid generation happens in a separate worker process. SDK function schemas are native and strict; Pydantic validation remains local. No blocking SDK call is placed directly in an async endpoint. Generation retries are disabled to avoid hidden paid replays.
- **Safe visible summaries.** Final numbers derive from executed rows. Model prose is not displayed as an unchecked factual interpretation. The public plan is an inspectable proposal, and execution receipts expose the result's practical limits.
- **Vercel for the demonstration, containers/Postgres for durable execution.** The demo is genuinely interactive over synthetic data, with explicit browser-session history. Ephemeral serverless state is not called a persistent production backend. The private deployment selects its configured provider.
- **Conservative failure recovery.** Expired or shutdown ownership cannot publish. Interrupted work requires explicit new admission, rather than silently rerunning model requests. This sacrifices automatic mid-run recovery to keep costs and publication behavior clear.
- **Explicit identity scope.** HttpOnly cookies, database-backed users/roles and owner-scoped histories improve the original token-localStorage design. The current private identity boundary is application users/roles; it does not assert enterprise warehouse row permissions.

- **Executable comparison tool over prompt-only semantics.** Five reviewed metrics justify an owned typed compiler with explicit compatible dimensions and denominators. The original exploratory SQL path remains with its narrower guarantee. MetricFlow was considered as a reference; no unused dbt dependency or unverified compatibility is added.
- **One statement for comparative evidence.** Independent total/segment aggregation branches use the same statement snapshot, avoiding drift across model rounds. This is not a stored replayable warehouse snapshot.
- **Application verification and descriptive Shapley accounting.** Arithmetic, data-quality checks and report publication are application-owned. Three-factor interaction sharing reconciles volume/mix/unit-cost components; it does not establish causes. Undefined segment unit costs disable factor attribution rather than silently inventing a price.
- **Portable evidence, no signature claim.** Canonicalized numeric fingerprint plus an offline recalculation catches changed content/inconsistent reports. The artifact is unsigned and cannot authenticate its source. See [metric investigation design](architecture/SEMANTIC-INVESTIGATIONS.md).

- **Distinct evidence studio.** Warm light surfaces and an indigo rail distinguish file analytics from the plum warehouse studio. Violet identifies analytical tasks, teal marks checked results, and coral separates exclusions and negative contributions. Colour supplements labels and exact values. Responsive task launchers connect both workflows; saved reports expose actual signed run metadata rather than presentation-only badges.
- **Technical review path.** README → technical report → source-linked evidence replaces decorative banners and repeated development checklists. Dated narratives remain in project history. Both continuous demonstrations capture actual browser interaction and hash all frontend source/styles, static players, backend code and capture scripts.
